# DENCAL

一般病院の院内サーバー・PCでの動作を想定した電子カルテの試作です。機能を一つずつ実装しながら画面とデータ構造を調整します。

**実務利用前の試作です。架空データのみで確認してください。**

外来カルテ診療、受付・会計算定、バックアップ・保存性、安全管理・監査証跡の4画面があります。

## 起動

Node.js 22.13以降と Python 3.10以降（SQLite 3.31以降）を使用します。

```sh
npm ci
npm run db:init
npm run dev
```

Viteが表示するローカルURLを開き、DB初期化時に端末へ表示された職員IDとパスワードでログインします。パスワードはアカウントごとに生成され、初期化時にのみ表示されます。

| 職員ID | 最低職種 | この職種から利用できる操作 |
| --- | --- | --- |
| `demo-reception` | 受付 | 外来カルテ閲覧、患者登録、受付・会計デモ |
| `demo-nurse` | 看護師 | バイタル・アレルギー登録デモ |
| `demo-physician` | 医師 | SOAP編集・確定、処方・検査指示、紹介状のテキスト出力 |
| `demo-admin` | 管理者 | 公式マスターの取り込み、全カルテのデモJSON出力、バックアップ・安全管理・監査デモ |

権限は **管理者 ＞ 医師 ＞ 看護師 ＞ 受付** の順に下位の操作を継承します。職種を変える場合はログアウトして別の職員IDでログインします。セッションは30分で失効し、離席操作でも終了します。

サーバーは患者一覧、個別カルテ、更新、確定、出力のリクエストごとに職種と対象患者の担当部署を確認します。管理者は全部署、その他の職種は所属部署の患者にアクセスできます。所属が未設定の職員には患者へのアクセス権がありません。デモの受付・看護師・医師は総合診療科に所属します。新規患者は登録者の所属部署に割り当てられ、所属未設定の管理者が登録する場合は総合診療科に割り当てられます。

二要素認証（2FA）は、実務利用に向けた開発の最終段階で実装する予定です。開発中は動作確認のためにログインとログアウトを頻繁に繰り返すため、認証手順が煩雑になることを避けるためです。

`db:init` は `data/dencal.sqlite3` を新規作成し、既存DBの上書きは拒否します。スキーマバージョン2・3のDBは、最初のAPIリクエストで既存の職員・セッション・マスターを保持したままバージョン4へ移行します。診療用テーブルと初期サンプルは、この移行時に作成します。別のファイルを新規作成する場合は、たとえば `npm run db:init -- data/auth-demo.sqlite3` で作成し、サーバー起動時の環境変数 `DENCAL_DB` に同じパスを指定してください。

職員認証・所属部署・セッション・公式マスター・診療録をSQLiteに保存します。診療データの試算やバックアップ画面は試作です。

## 診療録の保存・確定・訂正

1. 医師または管理者で患者を開き、SOAPを入力して **下書きを保存** を押します。
2. **診療録を確定** を押すと、SOAP・傷病名・処方・検査オーダの確定版を作成し、最終入力者・確定者・日時を記録します。
3. 確定後は理由を入力して **訂正を開始** します。訂正の入力を保存し、**訂正版を確定** すると、新しい版が履歴に追加されます。

保存した下書きと確定版は再起動後も残ります。未保存のSOAP入力は画面内に保持されます。同じ下書きを別画面で更新した場合、古い版を基にした保存・確定は拒否されます。確定版はSQLiteのトリガーで上書きと削除を拒否し、参照時に版ごとのSHA-256を検証します。HPKI電子署名、信頼できるタイムスタンプ、実DBのバックアップ・復元は今後の実装対象です。

## マスターと外部連携

1. 管理者でログインし、上部の **マスター管理** を開きます。
2. 厚生労働省の配布ページから令和8年度版の全件マスターを取得します。ZIPを解凍し、CSV・TXTを元のファイル名で一つずつ取り込みます。
3. 医師または管理者で **外来カルテ診療** を開き、登録傷病名・処方オーダ・検査オーダから候補を検索して追加します。

| 対象 | 展開後のファイル名の例 | 公式配布元 |
| --- | --- | --- |
| 傷病名 | `b_20260601.txt` | [厚労省 傷病名・修飾語マスター](https://shinryohoshu.mhlw.go.jp/shinryohoshu/standardMenu/doStandardMasterBz/) |
| 医薬品 | `y_20261013.csv` | [厚労省 基本マスター全件ダウンロード](https://shinryohoshu.mhlw.go.jp/shinryohoshu/downloadMenu/) |
| 医科診療行為 | `s_20261102.csv` | [厚労省 基本マスター全件ダウンロード](https://shinryohoshu.mhlw.go.jp/shinryohoshu/downloadMenu/) |

取り込み・検索はDENCAL自身のAPIとSQLiteで完結します。マスターは利用者が公式サイトから取得します。検索は日本時間の当日に利用できる最新の取込版を使います。処方候補は内用薬・外用薬、検査候補は入院専用を除く医科診療行為マスターの検査・病理診断の項目です。傷病名・医薬品のレセ電算コードと、医薬品の薬価基準収載医薬品コードを区別して扱います。[マスターファイル仕様説明書](https://www.hpdx.or.jp/seikyushiharai/tensuhyo/kihonmasta/)

公式マスターは名称・規格の選択に使います。処方の用法・用量・日数は入力者が指定します。処方の照合は薬剤名と同一薬剤の重複候補に限ります。禁忌・相互作用・腎機能別用量や、検査点数の正式な算定は未実装です。選択したカルテ明細と選択時のマスター参照情報はSQLiteに保存され、確定時に版の一部として固定されます。

共通算定モジュールは利用しません。医療機関名義での契約・接続手続きが必要なため、試作段階では同モジュールとオンライン資格確認に接続していません。診療報酬の計算は将来、独自の算定機能と連携して行う設計です。画面の試算値は動作確認用です。
