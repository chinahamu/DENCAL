# 外来診療録の画面とデータ構造

添付のKizunaEMRを参考に、患者・受診の識別情報を上部に集約し、SOAPと処方指示を同じ受診画面に置く。SOAPは広い画面では2列、狭い画面では1列。確定前の確認、確定後の参照、訂正履歴にも同じ項目順を使う。受付職員には受診の識別情報を表示し、SOAPと処方指示は医師に限定する。

## 診療録と処方指示

| データ | 識別子・関連 | 保持する内容 |
| --- | --- | --- |
| 患者 | 患者ID | 患者番号、氏名、生年月日 |
| 外来受診 | 受診ID、患者ID | 診療科、来院日、受付職員 |
| 診療録 | 受診IDにつき1件 | S、O、A、Pの各テキスト、下書きの版、作成・保存日時、入力者、確定日時・確定者 |
| 確定後の訂正 | 受診IDと訂正版 | 訂正後のSOAP全体、訂正理由、訂正者、訂正日時。確定時のSOAPと過去の訂正版は保持する |
| 処方指示 | 指示ID、受診ID | 試作の薬剤名、用量・単位、用法、日数、指示者・日時。投薬実施とは別の記録 |
| 監査 | 操作者ID、受診ID | 操作、日時、結果。SOAP本文・処方入力値・訂正理由は含めない |

A欄は医師の評価、P欄は治療方針を記載する自由文。コード付きの傷病、処方、診療行為はそれぞれの明細で管理する。下書き保存・確定は保存済みの版と照合し、古い版の送信を拒否する。確定したSOAPと処方指示は別の記録であり、SOAP確定に処方指示の確定や投薬実施は連動しない。

## マスター取込と参照の設計

薬剤、傷病名、医科診療行為は別途インポートする。初期の取込元候補は厚労省の基本マスターファイル。各体系のコードを区別し、異なるコード体系での同値性は明示的な対応データで管理する。[診療報酬情報提供サービス](https://shinryohoshu.mhlw.go.jp/shinryohoshu/infoMenu/)

| 将来のデータ | 取込・参照の契約 |
| --- | --- |
| マスター取込版 | 種別、提供元、公開版、適用期間、入力ファイルのハッシュ、取込日時を持つ。同じ版・内容の再取込は重複させず、検証済みの版をまとめて有効化する |
| マスター項目 | 取込版、コード体系、コード、表示名、適用期間を持つ。旧版を保持し、診療日時点で有効な項目を検索する |
| 薬剤明細 | 処方指示にマスター項目の参照と選択時のコード・名称を保存し、用量・単位・用法・日数を指示側に保持する |
| 傷病明細 | 患者と登録元の受診を紐付ける。マスター項目の参照と選択時のコード・名称に加え、開始日、主病の区分、転帰を保持する |
| 診療行為明細 | 受診とマスター項目を紐付け、選択時のコード・名称、実施日時・数量・実施者を保持する。指示と実施を区別する |

有効なマスターを選択できない場合、マスター連携後の画面は未取込を明示し、コード選択による登録を止める。マスター更新時に過去の記録の表示名やコードを書き換えない。RECEPTには実施済みの請求対象データを連携し、診療報酬の算定はRECEPTが担当する。

今回実装するのはSOAPの保存構造と診療録画面。取込処理・マスター検索・コード付き明細は別途実装する。現行の処方欄はマスター未接続と表示し、架空データによる操作確認に使う。
